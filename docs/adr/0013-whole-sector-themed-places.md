# Whole-sector themed places: AI description plus deterministic ground

A Sector becomes one complete, self-contained themed place that is walkable edge
to edge across its full 440 × 440 yards. The AI produces only a compact, versioned
**sector description**. A shared, integer-only, versioned **builder** expands that
description plus a seed into the sector's complete ground, identically on the
server and the client.

This supersedes [ADR 0003](0003-imperial-world-scale.md)'s clause that a Sector's
fine Tile detail covers only a bounded ±48 sub-area. It also supersedes, for new
sectors, [ADR 0012](0012-sector-detail-placement.md)'s server-pinned detail patch
as the ground model. It applies [ADR 0009](0009-dm-guild-semantic-world-pipeline.md)'s
deterministic-generative sandwich at sector scope:
`AI description → validation → Canon → deterministic builder`.

Producer decision: 2026-10-02. Implementation: Epic
[#1389](https://github.com/vnvalentin/project0/issues/1389) (Milestone 12, slice
group M12.2). This record decides direction and contracts; it does not claim
runtime acceptance.

## Context

Under ADR 0003 and ADR 0012, a sector blueprint *is* its ground: a list of 1-yard
tiles from the model. Ground size is therefore capped by model output size.

- Detail is at most 97 × 97 yards, placed around the entry point; the fallback is
  about 9 × 9 yards.
- The rest of each sector is unwalkable void. Players are held at boundaries, and
  most neighbouring sectors are unreachable
  ([#1374](https://github.com/vnvalentin/project0/issues/1374)).
- Producing even that patch took 209–1288+ tokens and 22–180+ s on the deployed
  model and hardware. None of 23 requests fit the 3.0 s cutoff
  ([#1360](https://github.com/vnvalentin/project0/issues/1360)).

ADR 0003 itself left "what occupies the non-detailed remainder" open. Fully tiling
a sector at 1-yard fidelity (about 194k cells) cannot be generated by a model.

## Decision

1. **Sector footprint.** The sector is the place. Its span stays 440 yards
   (`WorldScale.SECTOR_EDGE_UNITS`), placed at its global grid offset
   `(sector_x × 440, sector_z × 440)` (Epic #1063). The whole span is walkable
   ground, at roughly 90 s to cross at the authoritative move speed.
2. **Sector description (AI output).** A versioned, bounded contract. It names a
   theme from the server-owned archetype profiles
   ([#1062](https://github.com/vnvalentin/project0/issues/1062)), closed-enum biome
   tags, edge ports, a bounded path graph, and a bounded set of landmarks with
   coarse anchors. It is small enough to serialize in about 150 tokens. It is
   validated by an unchanged-in-spirit gate: a semantic validator plus a literal
   JSON schema. It never contains tiles, coordinates finer than its coarse anchors,
   or authority.
3. **Deterministic builder.** It lives in `shared/` and uses integer maths only,
   with a self-contained integer PRNG, no engine RNG and no float decisions. A
   `BUILDER_VERSION` is recorded with every build. Given (description, seed,
   builder version) it produces the complete walkability and height-class grid,
   guaranteeing that every edge port is mutually reachable and every landmark is
   reachable. The server uses the grid for movement authority. The client renders
   from the same grid and may add presentation, such as terrain shaping and
   modular prefabs, that never changes walkability.
4. **Canon.** Canon stores the validated description, the seed and the builder
   version, not tiles. Re-entry, restart and other clients rebuild identical ground
   with no model call. A builder change that alters output must bump
   `BUILDER_VERSION`, and existing Canon must keep rebuilding with the version it
   was committed under.
5. **Fallback.** With no valid model description inside the cutoff, the server
   derives a default description from the seed and the theme, instantly, and the
   builder fills the whole sector. Pass 1 repair and the Pass 2 template
   ([#1361](https://github.com/vnvalentin/project0/issues/1361)) apply to
   descriptions.
6. **Unchanged.** Imperial scale (1 unit = 1 yard), the 1-yard Tile, server
   authority, immutable first-commit Canon and the append-only mutation log, and
   the #551 timing budgets (3.0 s cutoff, 200 ms fallback, 300 ms commit, 500 ms
   presentation, 4.0 s total). Existing v1–v5 Canon blueprints remain valid and
   replayable under their original model.

## Consequences

- Every sector becomes a full place a player can cross. Neighbours become
  reachable, which re-enables generating sectors ahead of the player.
- The model's job shrinks to a short description, so fitting the 3.0 s cutoff
  becomes plausible ([#1393](https://github.com/vnvalentin/project0/issues/1393)
  measures it). Fallback becomes instant and whole-sector.
- Cross-engine determinism becomes a hard requirement: the server runs Godot 4.3
  and the client Godot 4.7.2. It is proven by a golden-hash corpus
  ([#1392](https://github.com/vnvalentin/project0/issues/1392)).
- New work: the description schema
  ([#1390](https://github.com/vnvalentin/project0/issues/1390)), the builder
  ([#1391](https://github.com/vnvalentin/project0/issues/1391)), then server/Canon
  and client-presentation Epics under Feature #551.
- Out of scope here: dungeon interiors (planned as entrances to separate
  interiors), rich client visuals, sector residency/streaming (#1063), and
  combat content.
- Milestone 2 closes on the small-patch model and does not depend on this
  decision ([#551](https://github.com/vnvalentin/project0/issues/551)).
