# Server-Pinned Fine Detail Within Stable Sectors

> Superseded for new sectors by [ADR 0013](0013-whole-sector-themed-places.md)
> (2026-10-02). Existing v5 Canon keeps this placement contract.

Issue [#1242](https://github.com/vnvalentin/project0/issues/1242) preserves
[ADR 0003](0003-imperial-world-scale.md)'s 440-yard sector identities and bounded
one-yard tiles. Blueprint schema v5 adds an explicit server-owned `detail_origin`
translation; v1-v4 placement, the reserved town, entity identity and immutable
Canon are not reinterpreted. This decision is an implementation contract, not a
claim that its runtime acceptance has passed.

## Coordinates And Ownership

World position is sector-grid offset plus detail origin plus detail-local position.
The inverse subtracts the same offsets. Blueprint X/Y mean world X/Z; vertical
position is unchanged. Sector membership remains floor(world / 440), including
negative coordinates and exact boundaries. The reserved town retains its existing
geometry and membership override.

For the first collision-resolved ingress, the server chooses each detail-origin
component as floor(sector-relative ingress), clamped to integers 0 through 439.
Nonfinite ingress or a mismatched sector is rejected. Selection happens before
generation and is pinned for the request, all waiters and the resulting Canon.
The model receives the required local ingress but cannot choose another placement.

In v5, the existing `origin` coordinate names the server-pinned entry tile in
detail-local coordinates, using floor(local + 0.5) with half-open tile membership.
This version-specific meaning does not change legacy origin handling. Fine tile,
structure and spawn coordinates retain the existing bounds and count limits.
Metadata outside its version or conflicting with the pinned placement is rejected.

## Geometry, Clearance And Admission

Ground and navigation rectangles are clipped to the owning sector's horizontal
extent. Adjacent sectors can meet at an edge but do not gain authority over each
other. Generated detail must not replace any reserved-town tile or intersect its
solid geometry; the fallback omits reserved-town cells. Shared conversion rules
apply once to geometry roots, structure/spawn anchors and collision queries.

Navigation rectangles use the actual one-yard tile extent in every schema. The
old inclusive/exclusive-end mismatch added one extra row and column to navigation;
correcting that overhang does not move legacy tiles, rendered ground or Canon.

Walkable detail is the four-neighbor component containing the committed entry
tile, excluding solid tiles and structure footprints. Other islands and the
unrepresented sector remainder cannot earn movement admission. The actor center
must be supported by this component and belong to the requested sector; its
0.4-yard horizontal clearance is checked against solid geometry, including town
walls at the join. Ground-support membership is center-based, matching existing
movement, not a claim that the entire capsule footprint belongs to one sector.

A matching peer/connection/Character/journey/presentation ACK remains necessary.
It is earned by actual client navigation completion, not fabricated by a positive
test. It does not waive connected coverage or collision. The presentation identity
includes the complete canonical blueprint, including placement and entry tile.
Navigation endpoints must lie in the acknowledged component; a disconnected island
or neighboring region must not make an unsafe local presentation appear ready.

Each v5 readiness node retains its coverage model and owns a separate navigation
map. Navigation polygons use matching cell edges and Godot's polygon clipping
and triangulation to exclude solid-cell clearance; rendered ground remains
merged. The node releases its map on exit. Rejection queues each owned child
once, without waiting synchronously for deferred deletion to reduce child count.

## Generation And Persistence

The server validates ingress coverage and overlap before Canon publication.
Invalid/unreachable generation may select a deterministic bounded floor patch at
the same placement, preserving the original generation reason and a separate
placement/fallback outcome. There is no extra model retry or longer deadline.
Only a safe, connected result is persisted and offered for presentation.

The initial placement and entry tile are stored atomically with the blueprint.
Reentry/restart uses those stored values; another waiter or distant later ingress
cannot reanchor them. Unsupported later ingress fails closed. Existing unusable
Canon is not repaired, rewritten or regenerated by this change. Tests use owned
fresh state and retain legacy fixtures. Multi-patch expansion remains out of scope.

Clients that cannot interpret v5 must be rejected by the existing explicit
client/server compatibility gate before gameplay; unsupported schema fails closed
at presentation as defense in depth. New candidate packages are distinct from
immutable 0.14.13/0.14.14. No publication or deployment is part of this decision.

The pre-auth handshake advances to schema 2 and declares
`blueprint_schema_version: 5`. The server requires that capability in addition to
the existing exact build-version match. The RPC signature remains a Dictionary;
no login, signed assertion, Character ownership or spawn rule is bypassed.
Legacy handshake schema 1 and missing/unsupported capability fail closed even
when an operator configures the same build-version string.

Rollback reverts only this correction and restores compatible artifacts. Preserve
v5 databases as evidence; never open or downgrade them with an incompatible binary.
Validation remains split by runtime ownership: real Canon on the isolated Linux
server, real presentation/navigation on Windows, and bounded paired/player proof
before closing #1242. #1230's grounded spawn and saved-position semantics remain
unchanged.
