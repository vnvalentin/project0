## #1341 bounded implementation brief — item identity contracts (2026-10-02)

Owner: `/root/ledger_audit`; governing epic #1341; parent Feature #950 / Theme #749; Milestone 3, named slice M3.2. This additive increment leaves the epic open.

**Outcome and scope.** Provide pure parse/serialize public seams for the exact ItemDefinition and ItemInstance fields accepted in [decision #306](https://github.com/vnvalentin/project0/issues/306#issuecomment-5736961246). Preserve the existing `shared/item_contract.gd` and its 14 slots, category, binding and effect semantics. Reject malformed, unknown, unpinned, incompatible, over-stack and owner/location-ambiguous records. Definition revisions are opaque strings; instance revisions and ticks are nonnegative integers. Definitions expose closed immutable snapshots, and instance parsing requires their pinned definition.

**SDD.** Add `shared/item_definition.gd` and `shared/item_instance.gd` with `from_wire_dict` and `to_wire_dict`. Factories return deterministic outcome/detail/value envelopes; failed parsing returns no value. Serializing and parsing copy nested dictionaries. Definitions carry definition_id/revision, item_class, compatible slot, category, maximum_stack, binding_policy and fixed base_effect. Instances carry instance_id, pinned definition identity/revision, quantity, authoritative owner, typed owner-relative location, bound_character_id, acquisition provenance, instance_revision and terminal metadata. Owners are character or world_container; locations are equipped(slot), carried(container_instance_id,index), or loot_position(source_id,index). Active records have one structurally compatible owner/location; retired records carry consumed/destroyed/merged reason, tick and operation ID with null live owner/location. Acquisition records carry source ID, operation ID and server tick. These representations implement #306; structural acceptance never establishes an authenticated actor, authority, a real acquisition or an exclusive persisted GUID.

**BDD/TDD and cheapest check.** Given a valid pinned definition and active/terminal instance, parsing then serializing returns an exact deterministic snapshot. Given unsupported/extra fields, unpinned definition/revision, noninteger or nonpositive/excess quantity, unsupported/incompatible slot, invalid owner/location, bad revision or terminal/live ambiguity, parsing fails closed. Given mutation of input or returned dictionaries, the parsed snapshot remains unchanged. Use one public behavior RED -> minimal GREEN at a time in `tests/unit/test_item_definition.gd` and `tests/unit/test_item_instance.gd`; do not test private helpers.

**Non-goals and unacceptable outcomes.** No SQLite schema, equipment mutation, crafting, transfers, stack split/merge implementation, actor receipts, restart proof, client changes or new dependencies. No ItemInstance durability/random-affix/custom-map field and no formula. The approved static creation property remains future integration; #306 is unchanged. No acceptance weakening or runtime claim from structural tests. Unacceptable: accepting unknown fields, rebinding revisions, retaining dictionary aliases, reviving a retired record, touching other workers' files or treating parsing as authorization. No ADR is needed: this is a representation of the already accepted decision, not a new architectural or product policy.
