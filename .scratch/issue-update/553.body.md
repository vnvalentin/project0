## Approved planning update





### What


Proposal validation requires role-specific bounded fields: World DM uses `campaign_refs`, `faction_refs`, `region_refs`, `global_event_refs`, `cross_character_refs`; Party DM uses `party_id`, `shared_objective_refs`, `relationship_refs`, `encounter_refs`; Personal DM uses `character_id`, `memory_refs`, `private_hook_refs`, explicitly selected `party_refs`, and explicitly selected `world_bulletin_refs`.





### Root Cause


Required-field validation must reject missing required fields and private fields belonging to another role. Optional fields become explicit empty lists and are never inferred.





### Metric


Rejections use bounded deterministic reasons: `missing_required_field`, `private_field_not_allowed`, or `invalid_bounded_value`; identical invalid inputs produce the same reason and no inferred fields.








## Authority ordering and bounded outcomes





### What


Enforce server > World > Party > Personal > client precedence for context proposals.





### Root Cause


Without canonical event sequence then stable proposal ID ordering within a role/scope, lower-priority values can overwrite higher-priority values and same-priority same-field conflicts are not rejected. Lower priority cannot overwrite higher priority; same-priority conflict applies no mutation.





### Metric


Verify bounded outcomes: `MALFORMED`, `UNSUPPORTED_SCHEMA`, `MISSING_REQUIRED_FIELD`, `INVALID_FIELD`, `UNAUTHORIZED_SCOPE`, `PRIVATE_CONTEXT_FORBIDDEN`, `AMBIGUOUS_INTENT`, `STALE_SNAPSHOT`, `CONFLICT`, `CONTEXT_UNAVAILABLE`, `TOO_LARGE`, `FALLBACK`. Each result contains only `outcome`, `reason_code`, `schema_version`, and a correlation/provenance reference; raw prompts and unrestricted model output are absent.








## Version and provenance contract


All proposals carry server-owned `schema_version`, `contract_version`, `prompt_version`, `model_id`, `model_version`, `builder_version`, `tuning_version`, `input_snapshot_hash`, and `provenance_id`. A proposal is stale/invalid when any required version differs from the active contract or when the input snapshot hash no longer matches; the server never silently migrates proposals across versions.





Provenance is bounded to `proposal_id`, `source_role`, `requesting_scope`, `input_snapshot_hash`, schema/contract/prompt/model versions, `canonical_event_sequence`, `outcome`, `reason_code`, `normalized_output_hash`, timestamps, and `correlation_id`. Raw prompts, credentials, private context, and unrestricted generated text are not persisted in provenance. Normalized bounded proposal content is retained separately only after validation and under storage policy.





## Authority invariants


Server-owned version checks are authoritative for server, world, party, personal, and client inputs. No layer may accept a proposal with a mismatched version or input snapshot hash, and no component may silently migrate it. Authority resolution must emit only bounded provenance fields and a correlation id; raw prompts, credentials, private context, and unrestricted generated text are excluded.

## Approved root-cause and metric boundaries

The server owns one active schema/contract/prompt/model/builder/tuning version tuple. Activation and rollback are explicit, versioned, and auditable; proposals using inactive tuples reject with `UNSUPPORTED_SCHEMA` or a stale-version outcome. Validated normalized proposals and bounded provenance are retained only for the related Canon revision plus its audit-retention window; rejected proposals persist only as bounded metadata for 30 days. Raw prompts, credentials, private context, and unrestricted model output are never retained. Replay requires exact schema, contract, prompt, model, builder, tuning, and input snapshot matches. Expired or mismatched records return `STALE_SNAPSHOT` or `UNSUPPORTED_SCHEMA`; the server never silently regenerates.

### Root Cause/Metric
Measure active-tuple lifecycle auditability, retention-denylist compliance, exact replay matching, and 100% rejection of expired/mismatched records without silent regeneration.
