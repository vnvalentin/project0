## 4Ws





- **Who:** server context assembler.


- **When:** before each model call.


- **Where:** server-only prompt boundary.


- **What:** assemble one bounded, explicitly selected target context for one source role and bind it to a canonical snapshot hash.





## Root Cause





No enforced single-role, least-privilege, reproducible context envelope.





## Measurable Metric





Identical inputs produce identical versioned snapshots; Personal DM receives Party/World context only when selected; private/cross-role data is excluded; changed inputs make proposals stale.

## Approved planning update





### What


Assemble only least-privilege context for one authenticated scope request, deduplicate references by stable ID, and order by `(scope_priority, canonical_event_sequence, stable_id)`.





### Root Cause


Filtering must precede assembly; World is background, Party is shared campaign state, and Personal is Character-local state. Optional missing context must be explicit empty sections, while required missing context rejects. Conflicts cannot be silently merged.





### Metric


Return a bounded conflict result for arbiter review and deterministic rejection for missing required context; include `snapshot_hash`, `schema_version`, ordered sections, and provenance.








## Precedence-aware context ordering and bounded errors





### What


Order context by server > World > Party > Personal > client precedence, then canonical event sequence and stable proposal ID within each role/scope.





### Root Cause


Unordered context assembly permits lower-priority overwrite and obscures same-priority same-field conflicts. Lower priority cannot overwrite higher priority; same-priority conflicts are rejected with no mutation.





### Metric


Verify precedence-aware context ordering and bounded error results containing only `outcome`, `reason_code`, `schema_version`, and a correlation/provenance reference. Allowed outcomes are `MALFORMED`, `UNSUPPORTED_SCHEMA`, `MISSING_REQUIRED_FIELD`, `INVALID_FIELD`, `UNAUTHORIZED_SCOPE`, `PRIVATE_CONTEXT_FORBIDDEN`, `AMBIGUOUS_INTENT`, `STALE_SNAPSHOT`, `CONFLICT`, `CONTEXT_UNAVAILABLE`, `TOO_LARGE`, and `FALLBACK`. Raw prompts/model output are absent.








## Version and provenance contract


All proposals carry server-owned `schema_version`, `contract_version`, `prompt_version`, `model_id`, `model_version`, `builder_version`, `tuning_version`, `input_snapshot_hash`, and `provenance_id`. A proposal is stale/invalid when any required version differs from the active contract or when the input snapshot hash no longer matches; the server never silently migrates proposals across versions.





Provenance is bounded to `proposal_id`, `source_role`, `requesting_scope`, `input_snapshot_hash`, schema/contract/prompt/model versions, `canonical_event_sequence`, `outcome`, `reason_code`, `normalized_output_hash`, timestamps, and `correlation_id`. Raw prompts, credentials, private context, and unrestricted generated text are not persisted in provenance. Normalized bounded proposal content is retained separately only after validation and under storage policy.





## Context snapshot and output invariants


Context snapshots carry and validate all server-owned versions plus `input_snapshot_hash`; a mismatch makes the snapshot stale/invalid and requires bounded rejection rather than silent migration. Outputs must be provenance-safe: retain only the approved bounded metadata and validated normalized content under storage policy, never raw prompts, credentials, private context, or unrestricted generated text.

## Approved root-cause and metric boundaries

Snapshot records have an explicit TTL and expiry status. Expired snapshots reject with `STALE_SNAPSHOT`; replay rejects on any schema, contract, prompt, model, builder, tuning, or input snapshot mismatch. The server never silently regenerates. Only validated normalized proposals and bounded provenance are retained for the related Canon revision plus its audit-retention window; rejected proposals are bounded metadata for 30 days. Raw prompts, credentials, private context, and unrestricted model output are never retained.

### Root Cause/Metric
Measure snapshot expiry rejection, exact replay mismatch rejection, provenance-safe retention, and zero forbidden-data retention or silent regeneration.
