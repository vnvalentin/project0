## Approved planning update

### Contract Decisions
**Input:** one authenticated scope request plus server-owned context snapshots. Least-privilege filtering occurs before assembly. References are deduplicated by stable ID and ordered by `(scope_priority, canonical_event_sequence, stable_id)`. World context is background; Party context is shared campaign state; Personal context is Character-local state. Conflicts are not silently merged; return a bounded conflict result for arbiter review. Missing optional context is an explicit empty section; missing required context rejects assembly.

**Output:** `snapshot_hash`, `schema_version`, ordered sections, and provenance.

### Measurable Component
Given identical authenticated input and snapshots, emit the deterministic filtered, stable-ID-deduplicated, canonically ordered output with explicit empty optional sections, bounded conflict results, required-context rejection, `snapshot_hash`, `schema_version`, and provenance.


## Precedence-aware assembly contract

### Contract Decisions
Assembly is precedence-aware: server-owned authoritative state > World DM proposal > Party DM proposal > Personal DM proposal > client input/presentation. Within one role/scope, order by canonical event sequence then stable proposal ID. Lower priority cannot overwrite higher priority. A same-priority same-field conflict produces no mutation and returns `CONFLICT`.

### Measurable Component
The bounded result shape contains only `outcome`, `reason_code`, `schema_version`, and a correlation/provenance reference. Outcomes are limited to `MALFORMED`, `UNSUPPORTED_SCHEMA`, `MISSING_REQUIRED_FIELD`, `INVALID_FIELD`, `UNAUTHORIZED_SCOPE`, `PRIVATE_CONTEXT_FORBIDDEN`, `AMBIGUOUS_INTENT`, `STALE_SNAPSHOT`, `CONFLICT`, `CONTEXT_UNAVAILABLE`, `TOO_LARGE`, and `FALLBACK`; raw prompts and unrestricted model output are absent.


## Version and provenance contract
All proposals carry server-owned `schema_version`, `contract_version`, `prompt_version`, `model_id`, `model_version`, `builder_version`, `tuning_version`, `input_snapshot_hash`, and `provenance_id`. A proposal is stale/invalid when any required version differs from the active contract or when the input snapshot hash no longer matches; the server never silently migrates proposals across versions.

Provenance is bounded to `proposal_id`, `source_role`, `requesting_scope`, `input_snapshot_hash`, schema/contract/prompt/model versions, `canonical_event_sequence`, `outcome`, `reason_code`, `normalized_output_hash`, timestamps, and `correlation_id`. Raw prompts, credentials, private context, and unrestricted generated text are not persisted in provenance. Normalized bounded proposal content is retained separately only after validation and under storage policy.

## Approved snapshot, replay, active-version, and evidence decisions

- Snapshot records have an explicit TTL and expiry status. Expired snapshots reject with `STALE_SNAPSHOT`; they are never silently regenerated.
- Replay is permitted only when schema, contract, prompt, model, builder, tuning, and input snapshot versions match exactly. Any mismatch rejects with `STALE_SNAPSHOT` or `UNSUPPORTED_SCHEMA`.
- The server owns one active schema/contract/prompt/model/builder/tuning tuple. Activation and rollback are explicit, versioned, and auditable; inactive tuples reject with `UNSUPPORTED_SCHEMA` or a stale-version outcome.
- Evidence is deterministic: all normal, invalid, boundary, conflict, stale-version, and privacy cases pass; two independent runs have identical normalized output and snapshot hashes; a machine-readable fixture artifact is retained; command exit is 0 with zero failed assertions and zero missing test cases. Results are posted to the Experiment issue with command, commit, artifact path/hash, and timestamp. Promotion is blocked until evidence is attached and reviewed.

### Measurable Component
Measure TTL expiry rejection, exact replay tuple matching, active-version enforcement, two-run hash equality, retained artifacts, and complete zero-failure/zero-missing-case evidence.
