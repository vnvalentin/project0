# Map: Organic LLM Village

## Destination

Replace the single 17×17 square hub with a larger, organic, walled,
researched-style starting village (gate, plaza, paths, clustered shops, houses,
extra flavor buildings) whose layout is generated by the local LLM but
validated so the required structures (10-house pool, Smithy, Armor Shop, Inn)
always exist — delivered as bounded, always-playable slices. Supersedes the
Slice 016 hard-coded square hub. See [Project Tracker](../../docs/PROJECT-TRACKER.md).

## Notes

- Research (2026-09-12): classic RPG starting towns are organic, non-grid, WALLED
  with a GATE, clustered shops (weapon/armor/item/inn/tavern/church), houses,
  a central plaza/well, paths, and FIELDS/"newbie yard" outside the walls where
  low-level monsters roam. Sources: Dragon Quest Tantegel/Brecconary (town+castle
  separate, walled, church/bank/inn/shops), EverQuest Qeynos (walled, zoned,
  gates, taverns, newbie yard outside). Player is small relative to buildings.
- Reopens the Slice 016 decision (hub hard-coded FOR reliability). Resolution:
  hybrid — LLM proposes the organic layout/flavor; server validates + guarantees
  required structures; falls back to a hand-authored organic fixture if the LLM
  output is unusable.
- Standing requirements (carried from prior maps): telemetry-first; SDD/BDD/TDD
  with focused + full GUT validation each slice; always-playable increments.
- Godot .tscn Transform3D needs EXACTLY 12 floats; new class_name scripts must
  be reached via preload const + Object typing, never a bare type annotation
  (repo headless class-cache lessons).

## Decisions so far

- Q1 Destination: a larger organic walled researched-style village replacing the
  square hub, LLM-generated + validated, delivered in slices.
- Q2 LLM vs reliability: hybrid — LLM proposes layout/flavor; server validates +
  deterministically guarantees required structures; hand-authored organic
  fixture is the fallback (never an unusable town).
- Q3 Scale & vocabulary: a schema v3 with larger bounds and organic tile kinds
  (path/gate/water/plaza/grass) + structure kinds (church/item_shop/tavern/well/
  market_stall); required kinds mandatory; v1/v2 stay valid; bump building/player
  scale so the player is small relative to the town.
- Q4 Monsters outside town: derive the town's boundary from the blueprint and
  place/clamp monster spawns outside it, replacing the fixed ±8.5 exclusion.
- Q5 Delivery order: (1) bigger organic hand-authored town that renders with the
  existing pipeline (instant visible win + future LLM fallback); (2) schema v3
  vocabulary + geometry + scale; (3) LLM generation + required-structure
  validation/fallback; (4) recompute monster exclusion from town bounds.

## Delivery slices (implementation roadmap)

- Slice 023: bigger organic hand-authored town (raise tile-count bound, organic
  non-square fixture using existing floor/wall/corridor + 4 structure kinds,
  spawn points + monster exclusion + FlatPlane resized to match). Renders with
  the existing translator — the instant visible win and the LLM fallback base.
- Slice 024: schema v3 organic vocabulary (path/plaza/gate/water/grass tiles +
  church/item_shop/tavern/well structures) + geometry translation + scale.
- Slice 025: LLM generation of the organic layout via the existing Ollama
  pipeline + required-structure validation/guarantee + fallback to the enriched
  fixture.
- Slice 026: derive the monster exclusion/spawn fields from the actual town
  bounds instead of a hard-coded constant.
