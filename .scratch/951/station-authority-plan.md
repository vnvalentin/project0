## Outcome, scope and hypothesis

An authenticated server Character can initialize a station interaction only inside a real active Area3D bound to a durable station/anchor/claim; final validation rechecks the current authenticated body, station, exterior anchor and permissions inside the caller's one managed SqliteStore transaction, before any action DML.

Unacceptable outcomes: trusting client in-volume/active/permission booleans; an arbitrary PhysicsBody impersonating an admitted Character; stale cached overlap accepting a moved Character; changed or destroyed binding; permission revocation passing final commit; nested transactions; rejection DML; opening live Canon/dashboard state; or reporting a full crafting/latency/lock/Windows outcome from component fixtures.

Hypothesis: a small closed station value, actual physics adapter and one same-store authority module can reject invalid/stale interaction state without action writes. Cheapest check: a real admitted-player/sensor/Area3D fixture proves in-volume admission, then moves the authoritative center outside before the next physics step and rejects immediately despite cached overlap. Real isolated SQLite tests then prove retained station identity, permission and effective exterior checks, zero rejection DML and reopen parity.

## SDD approved direction

1. Server-only WorkshopStationContract parses a closed version1 descriptor/record: schema_version, station_id, interior_id, anchor_revision, bounds_min, bounds_max, active, revision. IDs are bounded nonempty server-provisioned references. Anchor/station initial revision is1; inactive initial records are permitted but never authorize interaction. Intent contains only schema_version and station_id. Unknown fields or client identity/plot/geometry/active/permissions are rejected. Parsing creates independent typed values/snapshots, not authority.
2. Bounds are finite positive axis-aligned world-yard XYZ boxes, min-inclusive/max-exclusive for the authoritative Character center, wholly within #849's returned initial cell. Native Area3D uses a centered BoxShape3D of bounds_max-bounds_min, identity basis and unit scale; rotations, scale, transformed/missing/disabled shapes or mutable geometry are unsupported and fail closed. No new world conversion or ground-plane radius substitute is introduced. Spatial confirmed compatibility with its accepted v1 contract.
3. WorkshopCharacterSensor is a server-owned CharacterBody3D with a small centered sensor shape, no locomotion collision response. It binds only the existing admitted-player script, reads current LoginGateway Character/session epoch, and mirrors only authoritative server-player position. It rejects missing/replaced/revoked sessions, changed Character/peer, removed source and nonfinite pose. Source exit/unbind invalidates the sensor and outstanding interactions; signal connections and owned nodes are torn down. Sensor geometry is a query adapter, not a replacement movement/visual-body model.
4. WorkshopStationVolume owns real Area3D/BoxShape3D. Validation requires its exact supported binding/transform, registered authenticated sensor, fresh authoritative center containment, a settled pose and actual native overlaps_body. Godot4.3 documents overlap caches as updating once per physics step, not immediately after movement; therefore overlap alone is insufficient. No await occurs inside a transaction. https://docs.godotengine.org/en/4.3/classes/class_area3d.html#class-area3d-method-overlaps-body
5. WorkshopStationAuthority owns its SqliteStore, creates same-store InteriorAnchorRepository and ClaimPermitAuthority collaborators, persists one additive workshop_stations table with an anchor foreign key and closed retained record. Trusted registration validates current effective exterior through resolve_entry, exact interior/revision/cell bounds and independently registered claim/plot before its INSERT. Exact registration replay is read-only; conflicting or malformed retained data fails closed and remains preserved. No automatic repair/drop/rebind occurs.
6. Server-owned runtime station/sensor registrations and interaction handles pin actor/body/session, station descriptor and anchor revision. begin_interaction(sensor, closed_intent) performs fresh station/anchor/physics checks then permission initialization. Workshop mask is the root-approved server constant ENTER|MODIFY (9); clients never supply it. Future storage actions have their separate CONTAINER policy.
7. authorize_commit(sensor, server_held_handle) requires the same Store's existing managed transaction, performs read-only fresh station/anchor/physics checks, consumes the handle and calls #850 authorize_commit for current grant and membership reads. Any non-ok result requires the operation owner to abort before item SQL. This module does not begin a second transaction or expose arbitrary action-writer callbacks. A later closed item-operation owner combines this guard, permission reads, item SQL and receipt within one transaction. cancel/unbind are process-memory teardown without DML.
